Construire un système d’analyse automatisée de documents (tels que des rapports PDF, DOC, XL) centré sur 
les données des organisations (telles que les entreprises, les hôpitaux) pour construire un dataset (BD) 
structuré sur ces dernières. 
 
Explication des termes (LLM, Agent, Chatbot, RAG) dans le cadre du projet d’analyse de documents des 
organisations : 
 
LLM (Large Language Model) 
• 
Définition : Un modèle de langage de grande taille est une intelligence artificielle entraînée sur de 
grandes quantités de textes pour comprendre et générer du langage naturel. 
• 
Exemple : Si on devait s’intéresser sur les données climatiques des entreprises, un LLM (comme 
ChatGPT) peut lire des documents tels que PDF ou TXT, extraire des informations pertinentes (ex. : 
chiffres d’émissions de CO₂, secteur d’activité, taille de l’entreprise, politiques RSE) et aider à 
structurer ces données dans un tableau ou une base de données. 
 
Agent 
• 
Définition : Un agent est une entité autonome qui peut planifier, raisonner et exécuter des tâches de 
manière séquencée, souvent en utilisant un ou plusieurs LLM. 
• 
Exemple : On pourrait utiliser un agent pour : 
o 
Lire chaque fichier (PDF ou autre) automatiquement. 
o 
Identifier les informations pertinentes. 
o 
Poser des questions s’il manque des données. 
o 
Ajouter les données extraites dans un format structuré (tel que CSV, JSON). 
 
Chatbot 
• 
Définition : Un chatbot est une interface conversationnelle automatisée, souvent basée sur un LLM, 
avec laquelle un humain peut dialoguer. 
• 
Exemple : Un chatbot peut permettre d’interroger les documents ("Quelle est l’empreinte carbone de 
l’entreprise X ?") de manière interactive, mais il ne planifie pas de tâches complexes par lui-même 
comme un agent. 
 
RAG (Retrieval-Augmented Generation) 
• 
Définition : Une méthode d’IA où un modèle de langage (LLM) va chercher de l’information dans une 
base de données ou un corpus de documents avant de générer une réponse. 
o 
Retrieval = aller chercher de l'information dans les documents. 
o 
Augmented Generation = utiliser ces informations pour produire une réponse pertinente. 
• 
Exemple : Si l’on a des centaines de PDF, un système RAG peut être mis en place pour : 
o 
Indexer tous les documents. 
o 
Retrouver les passages pertinents selon la question ou le besoin. 
o 
Générer une réponse ou une donnée à inclure dans le dataset.

Étapes pour remplir la BD depuis des documents PDF 
1. Extraction du texte des documents de départ en PDF par exemple → avec des outils comme 
pdfplumber, PyMuPDF, ou des solutions OCR si scannés. 
2. Pré-traitement et parsing → repérage des zones contenant les données. 
3. Extraction avec LLM ou RAG → extraire les champs utiles. 
4. Validation humaine ou semi-automatisée (important dans un contexte scientifique). 
5. Insertion dans la BD.

Étape 1 – Modèle de base de données (en SQL / SQLite) 
Voici un script SQL utilisable pour créer ta base dans SQLite : 
-- Table des entreprises 
CREATE TABLE companies (id INTEGER PRIMARY KEY AUTOINCREMENT, 
    company_name TEXT NOT NULL, siret TEXT, country TEXT, industry_sector TEXT, company_size TEXT, 
    number_of_employees INTEGER); 
 
-- Table des rapports climat 
CREATE TABLE climate_reports (id INTEGER PRIMARY KEY AUTOINCREMENT, 
    company_id INTEGER, report_year INTEGER, report_title TEXT,  
    scope_1_emissions REAL, scope_2_emissions REAL, scope_3_emissions REAL, total_emissions REAL, 
    carbon_neutrality_target INTEGER, page_reference TEXT, 
    FOREIGN KEY (company_id) REFERENCES companies(id)); 
 
-- Table des politiques RSE 
CREATE TABLE sustainability_policies (id INTEGER PRIMARY KEY AUTOINCREMENT, 
    company_id INTEGER, has_sustainability_policy BOOLEAN, esg_goals TEXT, 
    climate_risk_management TEXT, certifications TEXT, 
    FOREIGN KEY (company_id) REFERENCES companies(id)); 
 
On pourrait exécuter ce script avec un outil comme DB Browser for SQLite ou directement dans un script 
Python.

Étape 2 – Script Python de base pour extraire et remplir la BD 
Ci-dessous un script Python minimal pour Lire un PDF, Extraire du texte (avec PyMuPDF) et Ajouter des 
données extraites dans SQLite. 
 
Installation des prérequis : pip install fitz PyMuPDF sqlite3 
Exemple de script Python : 
import fitz  # PyMuPDF 
import sqlite3 
 
# Connexion à la base de données 
conn = sqlite3.connect("climate_reporting.db") 
cursor = conn.cursor() 
 
# Exemple : Extraction texte d’un PDF 
def extract_text_from_pdf(pdf_path): 
    text = "" 
    with fitz.open(pdf_path) as doc: 
        for page in doc: 
            text += page.get_text() 
    return text 
 
# Supposons qu'on ait manuellement extrait quelques champs pour tester : 
def insert_test_data(): 
    # Ajout entreprise 
    cursor.execute(""" 
        INSERT INTO companies (company_name, siret, country, industry_sector, company_size, number_of_employees) 
        VALUES (?, ?, ?, ?, ?, ?) 
    """, ("Société ExEco", "12345678901234", "France", "Énergie", "ETI", 850)) 
 
    company_id = cursor.lastrowid 
 
    # Ajout rapport climatique 
    cursor.execute(""" 
        INSERT INTO climate_reports (company_id, report_year, report_title, scope_1_emissions, 
            scope_2_emissions, scope_3_emissions, total_emissions, carbon_neutrality_target, page_reference) 
        VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?) 
    """, (company_id, 2023, "Rapport RSE 2023", 1200.5, 850.2, 5300.7, 7351.4, 2030, "pages 12-15")) 
 
    # Ajout politique RSE 
    cursor.execute(""" 
        INSERT INTO sustainability_policies (company_id, has_sustainability_policy, esg_goals, 
            climate_risk_management, certifications) 
        VALUES (?, ?, ?, ?, ?) 
    """, (company_id, True, "Réduction de 40% CO2 d'ici 2028", "Suivi via comité climat trimestriel", "ISO 14001")) 
 
    conn.commit() 
 
# Exemple usage 
pdf_text = extract_text_from_pdf("rapport_exemple.pdf") 
# (On pourrait ensuite utiliser un LLM ici pour analyser `pdf_text`) 
 
insert_test_data() 
print("Exemple inséré.")
